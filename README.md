# PORTFOLIO

---

## 프로젝트 개요

개인 프로젝트와 개발 경험을 정리하고 공개하기 위해 제작한 포트폴리오 웹 애플리케이션입니다. 프로젝트를 WEB·GAME·ECT로 분류하고, 운영용 계정으로 로그인해 콘텐츠를 등록·수정·삭제할 수 있도록 구현했습니다.

메인 화면에는 자기소개와 기술 스택, 대표 프로젝트를 배치했습니다. 프로젝트별 상세 내용은 에디터에서 작성하고 데이터베이스에 저장해 관리하도록 구성했습니다.

- 개발 형태: Spring Boot 기반 웹 애플리케이션
- 개발 인원: 1인
- 개발 기간: 2일
- 담당 범위: 프론트엔드·백엔드 구현, 데이터베이스 구성 및 배포
- 배포 이력: 가비아 컨테이너 호스팅
- 운영 상태: 서비스 종료

## 구조 및 설계

### 서버 렌더링과 비동기 저장

Controller에서 조회한 데이터를 Model에 담아 Thymeleaf 템플릿으로 전달했습니다. 프로젝트 목록과 상세 화면은 서버에서 렌더링하고, 등록·수정·삭제는 JavaScript의 Fetch API로 요청하도록 구성했습니다.

데이터 처리는 Controller 또는 REST Controller에서 Service를 거쳐 MyBatis Mapper로 연결했습니다. SQL은 XML에서 관리하고, 요청과 조회 결과는 `PostDTO`로 전달했습니다.

### 포트폴리오 데이터 구성

프로젝트 정보는 단일 게시글 테이블로 관리했습니다. 제목·부제목·분류·썸네일 URL·Git 저장소 주소·HTML 본문을 저장하고, `web`, `game`, `ect` 중 하나의 분류를 선택하도록 구성했습니다.

메인의 자기소개와 대표 프로젝트 링크는 템플릿에 직접 작성했으며, 분류별 프로젝트 게시글은 데이터베이스에서 조회하도록 구현했습니다.

- 분류별 목록: WEB·GAME·ECT 프로젝트 카드 조회

## 구현

### 분류별 목록과 상세 조회

분류별 URL에서 전달받은 값을 기준으로 프로젝트를 조회하고, 게시글 ID 내림차순으로 정렬했습니다. 목록은 Thymeleaf의 `th:each`로 반복 렌더링하며 썸네일·제목·부제목을 카드 형태로 표시했습니다.

상세 화면에는 분류와 제목·부제목·본문을 출력하고, Git 저장소 주소가 입력된 경우에만 링크를 표시했습니다. 썸네일은 파일 업로드 대신 이미지 URL을 입력받아 목록의 배경 이미지로 사용했습니다.

### CKEditor를 이용한 등록·수정

본문 입력 영역에 CKEditor를 적용했습니다. 에디터에서 작성한 HTML과 제목·부제목·분류·썸네일 URL 등을 수집해 JSON으로 서버에 전달하고, MyBatis를 통해 저장했습니다.

작성과 수정은 하나의 템플릿을 재사용했습니다. Controller에서 신규 또는 기존 게시글 데이터와 `mode` 값을 전달하고, 이에 따라 입력값과 등록·수정 버튼을 변경했습니다.

제목·부제목·썸네일 URL·본문이 비어 있으면 제출을 막고 안내 메시지를 표시했습니다. 저장에 성공하면 서버가 반환한 게시글 ID를 이용해 상세 화면으로 이동하도록 구성했습니다.

상세 화면에서는 저장된 HTML을 `th:utext`로 렌더링해 에디터의 서식이 유지되도록 했습니다.

### 로그인 기반 콘텐츠 관리

Spring Security의 폼 로그인과 단일 인메모리 운영 계정을 사용했습니다. 계정 인증에는 BCrypt를 사용하고, 작성·수정·삭제 화면과 저장 요청 경로를 로그인 사용자에게만 허용했습니다.

Thymeleaf의 Spring Security 연동 기능으로 로그인 상태에 따라 등록·수정·삭제·로그아웃 버튼을 표시했습니다. 방문자는 로그인 없이 프로젝트 목록과 상세 내용을 조회할 수 있도록 구성했습니다.

삭제 전에는 확인창을 표시하고, 삭제 성공 후 해당 프로젝트의 분류 목록으로 이동하도록 구현했습니다.

### 공통 레이아웃과 모바일 대응

헤더와 푸터를 Thymeleaf fragment로 분리해 각 페이지에서 재사용했습니다. 현재 분류 메뉴에는 활성 상태를 표시하고, 로그인 여부에 따라 헤더의 관리 버튼을 변경했습니다.

프로젝트 목록은 기본 2열 Grid로 구성하고, 화면 너비가 768px 이하일 때 1열로 전환했습니다. 모바일에는 별도의 분류 메뉴를 표시하고 메인 화면의 기술 스택과 프로젝트 배치도 조정했습니다.

### 배포 구성

Gradle의 WAR 플러그인과 `SpringBootServletInitializer`를 적용해 외부 서블릿 컨테이너에서 실행할 수 있도록 구성했습니다.

가비아 컨테이너 호스팅에 배포하고 FileZilla를 이용해 운영 파일을 반영했습니다.

## 기술적 고민 및 개선점

### 로그인 만료와 작성 내용 보존

실제 운영 중 글을 작성하던 사이 로그인 상태가 만료되어 내용을 저장하지 못한 경험이 있었습니다. 현재 작성 화면에는 임시 저장과 복원 기능이 없고, 저장 요청에서도 인증 만료를 일반 오류와 구분하지 않아 작성 내용을 보존하기 어려웠습니다.

이를 통해 작성 시간이 긴 화면에서는 로그인 유지 정책과 함께 저장 실패 이후의 복구 흐름을 고려해야 한다는 점을 배웠습니다. 이후에는 작성 내용의 임시 저장·복원, 화면 이탈 안내, 인증 만료 시 재로그인 후 저장을 이어가는 흐름을 보완하고자 합니다.

### 저장 요청의 결과 확인

등록·수정 요청은 응답 상태를 확인하기 전에 JSON으로 변환하고 있어, 인증 만료나 서버 오류를 구체적으로 안내하기 어렵습니다.

후속 개선에서는 응답 상태에 따라 인증 오류와 저장 실패를 구분하고, 입력한 내용을 유지한 상태로 다시 시도할 수 있도록 처리하고자 합니다.
